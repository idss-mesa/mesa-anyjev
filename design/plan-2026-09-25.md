# mesa-anyjev: declarative, calibrated choices for MESA ontology and schema decisions

## Context

The MESA stack (mesa-mcp + mesa-ducklake) lets an agent tag iRODS data with OBO Foundry
ontology terms as AVUs. The neon-avu-eval experiment (7 NEON tables, 4 models, 2 reps) showed
the weakness of doing this with a free-running agent: every model chose only valid terms, but
models agreed on only 13-23% of exact CURIEs, and the same model agreed with itself on only
39-50% between runs. The choices inside that loop (which ontology, which candidate term among
OLS hits, which value, keep or drop) are implicit, uncalibrated, and unrepeatable.

AnyJev (Apache-2.0, nokia-applied-research) turns any open LLM into a Jev-style decision
model: a typed `Question` (choice / noul / score) over a `state` is answered from one prefill
of next-token logits, no generation, with a level that says how trustworthy the probability is
(`raw` < `L0` zero-label debiasing < `L1` temperature on 100-500 labels < `L2` closed-form head
on the hidden state, 100-300 labels, cheaper than L0).

Goal: a new repository `idss-mesa/mesa-anyjev` that makes MESA's choices *declarative*: a
reasoning model (Claude, or a local model on sparky-2) proposes which ontologies and schema
apply to a dataset; AnyJev then answers every multiple-choice step on the way to a definitive
AVU value as a calibrated probability, from a local model (sparky-2 via the CARC gateway, or
this GB10 workstation) or from Claude where no logits are available. Every decision is logged
next to the AVU it produced so the DuckLake history carries decision provenance.

**AnyJev contract (AnyJev/anyjev/)**
- `Question.choice(text, options<=26, name)`, `.noul(text)`, `.score(text, bins|levels)`;
  `q.key` = sha256 of the layout (kind, text, options); artifacts are keyed by it.
- `Decider(backend, level="L0"|"L1"|"L2"|"auto", prior="batch", ...)`; `decide(state,
  [questions], level=, require=)` -> `DecisionSet`; `decide_batch(states, q)`; `calibrate(q,
  states, labels)` (L1); `fit_head(q, states, labels)` (L2, needs `backend.hidden_states`);
  `observe(q, state, label, fit_at=30)` grows an L2 head from streamed labels;
  `export_artifacts()/load_artifacts()` JSON per model; `route(q)` serves a reworded /
  re-listed question from an existing head.
- `Decision`: `.probs`, `.distribution`, `.argmax`, `.confidence`, `.level`, `.diagnostics`
  (`order_flip_raw/l0`, `prior_method`, `permutations`, ...); `.require(level)` raises
  `LevelError`.
- Backend protocol: `tokenizer` (+`.encode`, `.chat_template`), `name`,
  `next_token_logprobs(prompts, token_ids)`; optional `score_shared`, `hidden_states`,
  `hidden_states_to`, `n_layers`. `render_state()` accepts str, dict (JSON), or chat list.
- Prompt: system "You are a decision function..." + `State:\n...\n\nQuestion: ...\nOptions:\nA.
  ...\nAnswer with the letter only.`; rendered through the tokenizer chat template with
  `enable_thinking=False` (matches Qwen3's `<think>\n\n</think>` no-think rendering, which the
  gateway probe reproduced).
- `bench/tasks/base.py`: `Task(name, question, items=[(state, label_idx)], license, source)`
  + `@register("name")`; `bench.run` writes results JSON. AGENTS.md rules that transfer to us:
  no fabricated numbers (every number names its JSON), level is mandatory on every decision,
  no hidden generation in decision mode, backends stay thin.
- `FakeBackend(content=lambda state, option: float, position_bias, label_prior)` parses the
  real prompt path and plants hidden states, so L0/L1/L2 are unit-testable on CPU in seconds.
- Deps: core = numpy only; `[hf]` = torch>=2.3 + transformers>=4.53. Python >=3.10. The
  `VLLMBackend` imports `transformers.AutoTokenizer` for the tokenizer only.

**MotherDuck `prompt_jev` (user pointer, read 2026-09-25; preview, may change)**
- MotherDuck SQL only (not local DuckDB); Lite or Business plan; us-east-1 / us-west-2; hosted
  TypeSafe Jev behind a scalar function: `prompt_jev(text_input, instructions, choice :=
  [labels or {label, description}])`, `score := [ordered levels]`, `noul := TRUE`, or
  `questions := {name: {type, instructions}, ...}` (one request per row, many questions).
  `instructions` and option lists must be SQL constants. Optional `batch_size` (single
  question packs 32 rows per request). Cost metered on input tokens (blog benchmark: $0.50 per
  100k rows, ~2,484 rows/s). NULL input or a failed request yields NULL, the query continues.
- Return: `STRUCT(choice VARCHAR, probabilities STRUCT(value VARCHAR, probability DOUBLE)[],
  confidence DOUBLE)` for choice; `score` (weighted position) for score; a DOUBLE probability
  for noul. Guidance: confidence under ~0.6 means overlapping or missing options (add "other"
  / "unclear"); criteria disjoint, short, same register, phrased as questions.
- Same three primitives as AnyJev (`Question.choice/score/noul`) and the same output shape
  (argmax + full distribution + confidence). Hosted Jev is therefore a third decision
  provider for the identical questions, reachable from SQL over the same DuckDB engine that
  mesa-ducklake already embeds, which makes whole-table batch scoring over the AVU history
  and over dataset cards a one-statement `CREATE TABLE ... AS SELECT prompt_jev(...)`.
- Constraints it adds: data leaves the host (fine for public NEON/CyVerse metadata, not for
  DUA-gated projects; needs a per-project hosted-providers switch as in mesa-nmdid rule 2);
  a `MOTHERDUCK_TOKEN` and `ATTACH 'md:'`; its probabilities are TypeSafe-calibrated but carry
  no AnyJev level, so the decision log must record `provider` and `calibration` separately
  from AnyJev's `level`.


## Design (synthesized from three independent plans, three judges, adversarial critique)

**Thesis.** Every choice MESA makes on the way to an AVU becomes a *fixed-key* AnyJev question
whose variable content lives in the *state*, so the question can accumulate a batch prior, an L1
temperature and an L2 head over time. The reasoning model (Claude, or carc-tools on the gateway)
only *plans*: which ontologies are in play, which columns to annotate, what to search. Code does
everything deterministic (OLS search, prefix filtering, dedup, canonical AVU build, DuckLake
write). AnyJev answers the multiple-choice steps with a calibrated probability and an explicit
level; anything that is not an AnyJev decision (a rule, a planner hint, a Claude structured
answer, a hosted-Jev answer) is recorded with `level='none'` and its own `method`, and a record
with no AnyJev level can never auto-write. Decisions are written to a mesa-anyjev-owned sidecar
*before* any iRODS write; `annotate` (decide, propose) and `apply` (write) are separate phases.

**Repository.** `github.com/idss-mesa/mesa-anyjev`, local at `~/github/idss-mesa/mesa-anyjev`.
Package `mesa_anyjev`, console script `mesa-anyjev`, MCP tools `mesa_decide_*` (surface
`decision`), env prefix `MESA_ANYJEV_<SECTION>__<FIELD>`, source tag `mesa-anyjev:<tool>:<outcome>`.
MIT (Regents of UNM); hatchling `src/` layout; Python >=3.11; uv; ruff/mypy strict; pytest
asyncio auto; markers `live`, `engine`, `requires_postgres`, `e2e`, all off by default.
Deps: `anyjev @ git+https://github.com/nokia-applied-research/AnyJev@795a497` (PyPI 0.0.2 lacks
L2), numpy, pydantic, httpx, pyyaml, structlog, duckdb, platformdirs. Extras: `mesa`
(mesa-mcp@8fbaedf, mesa-ducklake@7bc143f via `[tool.uv.sources]` git pins), `gateway`
(transformers, tokenizer only), `hf` (torch, transformers), `claude` (anthropic>=1.0), `pg`
(psycopg[binary]), `jev` (duckdb + motherduck extension at runtime), `docs`, `dev`.
'anyjev' appears only in the distribution/package name (descriptive use of the upstream project
name); tool names, env prefix and API paths use `decide`.

### Providers and levels

Two layers. *Backends* (AnyJev protocol): `FakeBackend` (CI), `GatewayBackend` (carc-fast L0/L1),
`HFBackend` (Qwen/Qwen3-8B bf16 on the GB10, all levels), `CompositeBackend`. *Providers*:
`AnyJevProvider`, `ClaudeStructuredProvider`, `HostedJevProvider`. Canonical model name for
artifacts = HF id slug `Qwen__Qwen3-8B` with `fitted_on {backend_kind, served_model,
served_revision, hf_model}` recorded; strict load refuses cross-backend use until the bench
shows gateway-vs-HF L0 agreement on the same items (the NVFP4 quant and the bf16 checkpoint are
not assumed interchangeable).

**MotherDuck hosted Jev (`HostedJevProvider` + `jev/` batch path).** Same three primitives, so
the same `Question` objects are answered by `prompt_jev(state_text, <question text>, choice :=
[<options>] | noul := TRUE | score := [...])` where `state_text` is byte-identical to AnyJev's
`render_state(state)` and the question text/options are the frozen constants from
`questions.py` (they must be SQL constants, which the frozen registry guarantees). Two entry
points: (a) per-batch provider for the pipeline (`ATTACH 'md:'` through the DuckDB engine
mesa-ducklake already embeds; `MOTHERDUCK_TOKEN` from env or keyring; never logged); (b)
`mesa-anyjev jev score --question <id> --states <parquet|run_id>` which materialises the state
batch as a table, runs one `CREATE TABLE ... AS SELECT prompt_jev(...)` (single-question calls
pack 32 rows per request), and `jev ingest` maps `STRUCT(choice, probabilities[], confidence)`
into `decisions` + `decision_options` with `provider='motherduck'`, `method='motherduck:prompt_jev'`,
`level='none'`, `calibration='vendor'`. The sidecar's `decision_options(option_text, prob)` and
`decisions.confidence` are the relational form of that STRUCT, and a DuckDB view
`mesa_anyjev.decisions_jev_shape` re-nests them so AnyJev rows and Jev rows compare in one query.
Policy: `allow_vendor_write=false` by default; a vendor record may become `auto` only after a
LOCO bench row cites its cov@5% on the same labels (`policy.jev.auto`, cite required). Data
residency: `policy.hosted_providers=false` per project by default (DUA-gated projects never
enable it; public NEON/CyVerse metadata may); the pipeline refuses to build a hosted provider
when it is false. Bench: hosted Jev is a third row per task (agreement with AnyJev L0/L1/L2 and
with consensus; ECE on labelled tasks), and its `confidence < 0.6` guidance is checked against
our abstain thresholds. Out of scope but recorded in DESIGN.md: MotherDuck-managed DuckLake as a
future mesa-ducklake catalog backend (it can ATTACH `ducklake:` catalogs) would let the whole
AVU history be scored in place with `prompt_jev`.

### Learning loop

Labels (option indices per (question_key, state)) with weight and source: curator picks 1.0
(one pick yields up to 8 rows: chosen Yes, offered others No), auto-written AVUs later deleted
through mesa-mcp 0.8, neon-avu-eval consensus 0.8/0.6 (term.fits: 303 candidate states, 92
positives; avu.keep: 572; aspect/ontology/value_kind from the 493 column-linked AVUs; documented
as agreement, not truth), Claude Batch teacher 0.5 (`teach submit --dry-run` estimates cost
first; distillation ceiling recorded), gold 1.0. Fitting: L1 `Decider.calibrate` (>=100 labels,
works on the gateway); L2 `Decider.fit_head` (HF/composite; min max(8, 2K); practical 100-300);
**leave-one-card-out is the only split that may set a threshold or promote a bundle**;
`learn promote` refuses regressions. Online: `record_human_pick` -> `observe(fit_at=30)` on
backends with hidden states. Wording changes rotate keys (lock test) -> `learn migrate-key`;
`Decider.route()` serves rewordings meanwhile.

## Amendments after the adversarial critique (three critics; verdicts ship-with-fixes, rework, ship-with-fixes)

All accepted. They supersede the sections above where they conflict.

**Blockers (AnyJev behaviours verified in `AnyJev/anyjev/decider.py`)**
- A1. `Decider.route()` matches any stored head with the same *kind and option texts*; every noul
  has options ('Yes','No'), so with `level='auto'` one fitted noul head would silently serve every
  other noul question at "L2". `AnyJevProvider` therefore resolves the level itself per exact
  `q.key` (L2 iff key in `_heads`, L1 iff key in `_artifacts`, else L0) and passes it explicitly;
  any record with `diagnostics.routed_from` set is stored at L0 with `routed_refused=True`. Test:
  fit a head for `term.fits` on the fake backend, ask `avu.keep` at auto, assert level != L2.
  File an upstream AnyJev issue (route() should require text match for noul).
- A2. Day-0 `term.fits` labels at `min_weight=0.6` are positives-only (92 Yes, 0 No):
  temperature scaling degenerates and cov@5% is trivially 100%. Fix: per-question `min_weight`
  in `policy_defaults.yaml` (term.fits 0.5 so consensus negatives enter); `labelled_states()`
  returns class counts; `learn fit` and `suggest_policy` refuse (`insufficient_negatives`) unless
  each class has >= 30 labels in the training fold and >= 5 in the held-out card;
  `test_policy_citations` parses the cited JSON and requires `n_neg >= 30`.

**Honesty of levels and probabilities**
- A3. `observe()` never fits inside a serving process (it would bypass the LOCO `promote` gate):
  serving stores labels only; fitting happens only through `learn fit` + `learn promote` (on the
  GB10, or a detached Decider). Implicit negatives from a pick ("other offered candidates")
  are `label_source='curator_implicit'`, weight 0.7; only an explicit "none of these" yields
  weight-1.0 negatives.
- A4. Under the gateway's top-20 readout a label missing in *any* cyclic shift erases the option
  (logmean over shifts). `missing_labels` is counted per `decide_batch` (the Decider dedups
  prompts, so per-decision attribution is impossible) and stored on `decision_groups`/`runs`;
  `WritePolicy.outcome()` caps any batch with `missing_labels > 0` at `rule`/`abstain`, flags
  `degraded=True`. The doctor reports per-option erasure rate at K=2/8/12; `max_choice_k` may be
  raised only when that rate is 0 on the fixture set.
- A5. L1 fitting runs on a Decider with `adaptive_shifts=False` (the sequential path freezes no
  prior into the artifact); a served record whose `prior_method` does not start with `frozen:`
  is stored as L0 with `l1_prior_missing=True`.
- A6. The batch prior is a process-wide running accumulator, so per-column asking is
  order-dependent. The pipeline stages each card: one `decide_batch` per question across all
  columns (annotate, aspect, ontology twin = 12 x columns states, value_kind), and
  `decider._running` is reset at `begin_run` so a run is a function of (card, artifacts).
  `bench e2e` *measures* rep1-vs-rep2 agreement per level instead of asserting determinism.
- A7. For noul, `Decision.confidence = max(p, 1-p)`; policy must threshold `p_true`.
  `DecisionRecord` gains `p_true`; `Thresholds.stat in {'p_true','confidence'}` (noul -> p_true,
  choice -> confidence); `decision_groups.group_margin` is distinct from `decisions.margin`.
- A8. `calibration: Literal['anyjev','typesafe','none']` is added to `DecisionRecord` and to
  `decisions` in migration 0001 (M0). Invariant: `probs IS NULL iff calibration='none'`; `level`
  stays the AnyJev level ('none' for every non-AnyJev provider). `auto` requires
  `calibration in policy.auto_calibrations` (prod default `('anyjev',)`) and a threshold keyed by
  (question, provider). Claude: calibration none, probs None. Hosted Jev: calibration typesafe,
  probs non-null, never auto until a cited bench row exists. `kind='score'` rows get
  `score_value REAL`. Diagnostics are cast with float()/int()/bool() before storage (numpy).
- A9. Thresholds derived in the bench must be computed on the same masked, renormalised
  distributions the pipeline applies (`meta.mask` per bench item; `masked=True` in results).
- A10. `canonical_model` defaults to the served repo id `RedHatAI/Qwen3-8B-NVFP4` until the
  doctor's parity record (label ids + chat-template hash vs `Qwen/Qwen3-8B`) is written into
  RESEARCH.md; `runs` gains `tokenizer_revision`. The carc-fast revision is
  `e391349c110709b87bfc2ad2fde3f50dc5839fd8` (from `carc-agents/models/carc-fast.yaml`; verify
  on the Hub in the doctor). Method gains `'unavailable'`; such rows store `model='n/a'`.
- A11. MRTR enumNames render `p(fits)=0.83 L1`; `decider_unavailable` groups render "unranked
  (decider unavailable)" with no p/level.

**Things that would not have run**
- B1. `handle_avu_from_term` is `async def`; `avu.build_avu` calls the two sync pieces it wraps
